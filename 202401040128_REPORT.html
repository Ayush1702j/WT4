1. Aim and Problem Statement

1.1 Aim

To design, develop, and deploy an asynchronous NodeJS HTTP server using native core modules (http, fs, events, stream, path, os) and modular custom modules that demonstrates strict server-side validation of incoming student registration payloads, proper HTTP status code handling (200 OK, 201 Created, 400 Bad Request, 409 Conflict), event-driven audit logging, readable stream piping for data exports, and file-based JSON persistence.

1.2 Problem Statement in Own Words

Client-side form validation is vulnerable to bypasses (e.g., direct API calls via Postman, curl, or disabled JavaScript). Robust web applications must execute authoritative validation on the server. The specific capabilities demonstrated in this application are:

  • Native HTTP Server: Implementing a pure NodeJS HTTP server without third-party frameworks, handling GET, POST, DELETE, and OPTIONS routing with CORS compliance.
  • Server-Side Validation Engine: Enforcing 9 validation rules on JSON payloads (regex for names, 7-10 digit PRN, RFC email format, 10-digit Indian phone, enum checks for department and year, numeric range for CGPA, and skills array).
  • Standardized HTTP Status Codes: Returning 201 Created on success, 400 Bad Request with a structured validation error array on invalid input, 409 Conflict on duplicate records, and 404 Not Found for missing endpoints.
  • NodeJS Events (EventEmitter): Emitting asynchronous domain events (request, studentRegistered, validationFailed, duplicateAttempt, streamExport) handled by a decoupled audit logger.
  • NodeJS Streams (stream.Readable & pipe): Ingesting request body chunks via streams, streaming dynamically generated CSV files (/api/stream/csv), and streaming raw server log files (/api/stream/logs).
  • File System Persistence (fs.promises): Reading, appending, and updating persistent JSON data stores (data/students.json) and audit logs (data/server.log).

3. Implementation and Key Code Explanation

3.1 Native HTTP Server & Stream Request Parsing (server.js)

Incoming request bodies are assembled asynchronously from the readable request stream: 

function parseRequestBody(req) {
  return new Promise((resolve, reject) => {
    let body = '';
    req.on('data', (chunk) => {
      body += chunk.toString();
      if (body.length > 1e6) { // 1MB flood protection
        req.connection.destroy();
        reject(new Error('Payload too large'));
      }
    });
    req.on('end', () => {
      if (!body.trim()) return resolve({});
      try {
        resolve(JSON.parse(body));
      } catch (err) {
        reject(new Error('Malformed JSON syntax in request body'));
      }
    });
    req.on('error', (err) => reject(err));
  });
}

3.2 Server-Side Validation Module (modules/validator.js)

function validateRegistration(data) {
  const errors = {};
  const sanitized = {};

  // Full Name: Alphabets and spaces only (3 to 50 chars)
  const rawName = (data.fullName || '').trim();
  if (!rawName) errors.fullName = 'Full Name is required.';
  else if (!/^[A-Za-z\s]{3,50}$/.test(rawName))
    errors.fullName = 'Full Name must contain only alphabets and spaces (3-50 chars).';
  else sanitized.fullName = sanitize(rawName);

  // PRN Number: 7 to 10 alphanumeric digits
  const rawPRN = (data.prn || '').trim();
  if (!rawPRN) errors.prn = 'PRN / Roll Number is required.';
  else if (!/^[A-Za-z0-9]{7,10}$/.test(rawPRN))
    errors.prn = 'PRN must be 7 to 10 alphanumeric characters (e.g. 2304362).';
  else sanitized.prn = sanitize(rawPRN).toUpperCase();

  // CGPA: Float between 0.00 and 10.00
  const rawCGPA = parseFloat(data.cgpa);
  if (isNaN(rawCGPA) || rawCGPA < 0.0 || rawCGPA > 10.0)
    errors.cgpa = 'CGPA must be a valid numeric value between 0.00 and 10.00.';
  else sanitized.cgpa = parseFloat(rawCGPA.toFixed(2));

  return { isValid: Object.keys(errors).length === 0, errors, sanitizedData: sanitized };
}

3.3 Event-Driven Logging with EventEmitter (modules/logger.js)

class ServerAuditEmitter extends EventEmitter {
  constructor() {
    super();
    this.setupListeners();
  }

  setupListeners() {
    this.on('studentRegistered', ({ studentId, prn, name, dept }) => {
      this.writeLog('SUCCESS', `Student Registered -> ID: ${studentId} | PRN: ${prn} | Name: "${name}"`);
    });

    this.on('validationFailed', ({ ip, errors, endpoint }) => {
      this.writeLog('WARN', `Validation Failed at ${endpoint} from IP ${ip} | Flagged: [${Object.keys(errors)}]`);
    });
  }

  writeLog(level, message) {
    const line = `[${new Date().toISOString()}] [${level}] ${message}\n`;
    fs.appendFile(LOG_FILE_PATH, line, () => {});
  }
}

5. Testing and Conclusion

5.1 What Works

  • High-performance native HTTP server built with pure NodeJS core modules (0 external dependencies).
  • Comprehensive server-side validation rejecting invalid data before it reaches the persistence layer.
  • Standardized REST responses with exact status codes: 201 Created, 400 Bad Request, 409 Conflict, 200 OK, 404 Not Found.
  • Decoupled event architecture using custom EventEmitter subclass for audit logging.
  • High-throughput data streaming for CSV exports and log inspection using NodeJS streams and pipe().
  • File-based JSON storage persisting student records across server restarts.

5.2 Limitations

  • File-based JSON storage is suitable for demonstration; production high-concurrency systems require ACID-compliant relational databases (PostgreSQL/MySQL) or MongoDB.
  • In-memory body parser limits single request payloads to 1MB to prevent Denial-of-Service attacks.

5.3 What I Learned

  • Understood the core NodeJS HTTP request lifecycle and how request bodies stream over TCP chunks.
  • Gained practical mastery of the EventEmitter pattern for non-blocking asynchronous event handling.
  • Learned to use Readable Streams and pipe() to transfer large files without memory exhaustion.
  • Appreciated why server-side validation is non-negotiable for enterprise application security.
